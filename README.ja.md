# ShanHai（海珊）

**法律テキスト証拠 Skill**

ShanHai は、法的・テキスト的証拠の構造化抽出と引用のための、独立して利用できるオープンソース Skill です。UTF-8 の法律テキストを読み取り、法的構造を検出し、正確な文字・バイト・行スパンを持つ証拠ユニットを出力します。成果物に対して再検証できる引用を再構築し、構造上の問題は推測で埋めず、区別された検査可能な結果として報告します。

暗黙の推論は行いません。読み取れなかった値は損失として、一意に定まらない位置は曖昧性として、文書構造の問題は型付きの診断として報告します。

* **単体利用は第一級のサポート対象モードです。** ShanHai は、非公開の SeaFlow ベースランタイムにアクセスすることなく、複製・テスト・利用できます。
* **SeaFlow との統合は任意です。** SeaFlow と統合する場合、ShanHai は公式の SeaFlow Skill／プラグインとして動作しますが、その統合は SeaFlow 側で実装されるものであり、単体利用に統合は必要ありません。

## 機能

以下は Skill が実行時に宣言する機能です。記載のないものは実装されていません。

| 機能 | サポート | 内容 |
| --- | --- | --- |
| 法律テキスト証拠ユニット | supported | 検出された「条」ごとに 1 つの証拠ユニットを出力し、加えて「章」のコンテナユニット、および条項が得られなかった文書のユニットを出力 |
| 構造診断 | supported | `empty_artifact`、`unsupported_structure`、`missing_marker`、`malformed_marker`、`numbering_gap`、`duplicate_marker`、`encoding_failure` — それぞれを区別して保持 |
| 正確なスパン位置 | supported | 条項ごとに文字スパン、UTF-8 バイトスパン、1 始まりの行スパンを記録し、成果物のバイト列から算出 |
| テキスト引用の再構築 | supported | 「条」、段落、または文字スパンから、正確で再検証可能な引用を再構築 |
| 段落分割 | partial | 段落は条項内の空行区切りブロック。単一段落の条項は 1 ブロックを出力 |
| 検索・ランキング | unsupported | 本 Skill には検索、ランキング、全文検索、類似度、曖昧一致が設計上存在しません |
| OCR・非テキスト入力 | unsupported | 読み取るのは UTF-8 テキストのみ。画像、PDF、バイナリ形式はテキスト成果物ではありません |
| 法的効力 | unsupported | 本 Skill はテキストが「どこにあるか」を記録するもので、そのテキストが現行か、適用可能か、権威的かについては何も主張しません |

曖昧性はエラーではなく結果です。重複した条マーカーはすべての候補を返し、いずれも選択しません。どこにも「最初の一致」によるフォールバックはありません。

ShanHai は、法的助言、法的意味推論、LLM 生成、自律エージェント、検証済みの法的権威、あらゆる法令形式のサポートを**提供しません**。

## 現在インデックス済みで検索可能な法源

以下の一覧は、**取り込み済みかつ検索可能**な法資料を対象とします。ShanHai はそのテキストを読み取り、正確な条項を特定できます。同一の法源に複数の言語版がある場合は、言語ごとに別項目として掲載します。別言語の表現が自動的に同等の権威を持つわけではないためです。

本リポジトリは **Skill であり、コーパスではありません**。提供するのは抽出機能のみです。**法源テキスト自体は本リポジトリでは配布されません**。したがって本リポジトリを複製しても、以下に挙げる法源は得られません。Skill と法源コーパスは別物です。

ShanHai 自身は検索もランキングも行いません。与えられた出典の中で条項を特定して引用するだけであり、突き合わせや選択は呼び出し側の責務です。

### ヘーグ／ヘーグ・ヴィスビー体系

ローカルに保持していますが、**ShanHai ではまだ検索できません**。

| 保持しているが未検索 | 理由 |
| --- | --- |
| 1924 年ヘーグ規則、1968 年ヴィスビー議定書、1979 年 SDR 議定書 | 英語の `Article N` 見出し |
| ヘーグ・ヴィスビー統合テキスト | 同じ 3 文書の派生統合版。こちらも英語の `Article N` 見出し |

したがって ShanHai は、条文を推測するのではなく、サポートされない構造として報告します。現在は検索も引用もできないため、上記の検索可能な法源には**意図的に**含めていません。

### 国連条約および関連資料

ローカルに保持していますが、**ShanHai ではまだ検索できません**。

| 保持しているが未検索 | 理由 |
| --- | --- |
| 1958 年ニューヨーク条約 | 中国語版は原理上検索可能だが、保持テキストに発行機関と寄託機関が示されていないため、レビュー待ちとして保留。英語版と 2 つの PDF は本 Skill では読めません |
| 2008 年ロッテルダム規則 | 権威が未確認の中国語版のみ検索可能で、うち 4 か条は一意に選択できない。英語版と 2 つの PDF は本 Skill では読めません |
| 1978 年ハンブルク規則 | 英語の `Article N` 見出し。その Common Understanding は条約の解釈附属書であり、独立した文書ではなく、単独では引用できません |
| 1982 年国連海洋法条約 | 英語の `Article N` 見出し |
| UK Public General Act 1995 c.21（候補） | スキャン画像 PDF。テキストから同一性を確認できません |

国連海洋法条約は「出典パッケージ」として保持しています。条約本文と、その不可分の附属書および最終文書の資料です。これらの附属書は条約の構成部分であり、独立した文書ではありません。

上記のロッテルダム規則の項目は、保持している表現版が*実際に検索可能*である唯一の例です。中国語テキストは条番号を解決しますが、4 つの条が複数の候補を返していずれも選択されず、その表現版の権威の状態も未確認です。制約が名称の隣に見えるように、上表ではなくここに掲載しています。

### 民法典に影響する既知の制約

中国語の民法典は検索可能ですが、**「千」を含む漢数字で書かれた一部の条番号は現在特定できません**。そのためそれらの条への引用は保持テキストから解決できません。実際に影響するのは 999 条より上の条文です。掲載した他の法源はすべて条レベルで解決します。同じ数字表記の制約は、別途維持管理されている生態環境法典のコピーでも独立に観測されました。


## 最小の単体利用例

必須のサーフェスは 1 つの関数だけです:

```python
from skills.shanhai import run_legal_text_evidence

result = run_legal_text_evidence("statute.txt", source_id="statute")

print(result.is_complete_success)          # 何か失われていれば False
for unit in result.units:
    print(unit.address.value, unit.loss)   # 正確な位置と、欠けているもの
```

`run_legal_text_evidence` は、ファイルシステムのパス、生のバイト列、または自分で構築した `TextArtifact` を受け取ります。返る実行結果には、証拠ユニット、実行診断、および読み取りが完全だったかについての正直な評価が含まれます。何も得られなかった文書でも、例外を送出するのではなく、損失を記録した結果を返します。

下位のエントリポイントもあります:

```python
from skills.shanhai import ShanHaiLegalTextEvidence, TextArtifact, FixtureTextBackend

artifact = TextArtifact.from_file("statute.txt", "statute")
result = ShanHaiLegalTextEvidence(FixtureTextBackend()).run(
    artifact, source_id="statute"
)
```

リポジトリには実行可能な例もあります:

```bash
python examples/shanhai_legal_text_example.py
```

```bash
python tests/run_all.py --quiet
```

ランタイム、サービス、兄弟チェックアウト、外部パスは不要です。専用の分離スイートがそれを証明します。`skills/` 配下のいずれかのモジュールが非公開ランタイムの import を取得すると失敗し、パッケージの import がそのようなモジュールを読み込まないことを確認し、**本リポジトリのみ**をパスに含む新しいインタプリタからエントリポイントと例を実行します。

## 既知の制約

* **UTF-8 の法律テキストのみ。** PDF、DOCX、OCR、表計算は対象外です。Skill の能力外の形式は、試すのではなく拒否されます。
* **中国語の法的マーカー。** 条と章の検出は、番号付きの中国語マーカー（`第X条`、`第X章`）を対象とします。`Article N` 形式のラテン見出しは本 Skill の範囲外であり、サポートされない構造として報告されます。
* **「千」を含む漢数字は解決されません。** 漢数字で書かれた一部の条番号は現在特定できず、それらへの引用は解決できません。これは数字の表記形式に固有のもので、条番号の大きさの問題ではありません。半角数字を使うテキストは影響を受けません。
* **目次と本体の章の曖昧性。** 目次内の章マーカーと本体の実際の章構造は、常に確実に区別できるわけではありません。また、編をまたいで番号が振り直される場合、章番号の重複は正当であり得ます。影響は章コンテキストのみで、条レベルの証拠は影響を受けず、盲目的な重複排除も行いません。
* **エンコーディングは UTF-8 のみ。** BOM のないレガシーエンコーディングは、推測せずエンコーディング失敗として報告されます。
* **段落分割は部分的。** 段落は空行区切りのブロックで、条項内部のより深い構造はモデル化していません。
* **検索・ランキングはありません。** 突き合わせと選択は呼び出し側の責務です。
* **法的効力の判断はありません。** 抽出と位置特定のみです。
* **プラットフォーム適格性。** Windows + CPython 3.13.14 で確認済みです。ランタイムは標準ライブラリのみを import するため、この環境に固定されるものではありませんが、他のバージョンやプラットフォームは確認していません。

## SeaFlow との関係

ShanHai は、独立して公開される 2 つのオープンソース Skill の 1 つです。SeaFlow はこれを公式 Skill／プラグインとして統合できます。単体利用に非公開の SeaFlow ベースランタイムへのアクセスは必要ありません。

依存の向きは一方向です:

```
SeaFlow（非公開ランタイム）  ---適応--->  ShanHai（本リポジトリ）
```

ShanHai が SeaFlow を import することはありません。SeaFlow を一度も使わなくても、ここにあるものは変わりません。

* SeaFlow の公開情報入口: <https://github.com/HuDeyi-66/SeaFlow>

本節のリンクは**発見用リンク**であり、ランタイム依存の宣言ではありません。

## 海珞（LuoHai）との関係

海珞（LuoHai） — 表形式証拠 Skill — は ShanHai の**兄弟 Skill** であり、依存ではありません。どちらの Skill も他方を import せず、その分離はテストで表明されています。

* LuoHai リポジトリ: <https://github.com/HuDeyi-66/Luo_Hai_Tables_Skill>
